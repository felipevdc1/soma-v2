# Amendment 1.3.0 — Orquestração eficiente

**Status:** APROVADA — Feature 025 em 2026-08-24
**Bump:** 1.2.1 → 1.3.0 (MINOR — altera o protocolo operacional de recuperação)

## Decisão normativa

Cada task recebe um executor, duas tentativas no máximo (inicial e uma correção), e nunca escalation automática. Checks determinísticos antecedem um revisor integrado; o segundo revisor exige risco independente declarado e lê o mesmo commit candidato.

Após blocker residual, o controller reutiliza `/tmp/soma-diagnostic-{runId}.json` como handoff durável com `candidate`, `proofs`, `residualFinding`, `nextDecision` e `dispatchRecord`. Não há ledger paralelo.

## Propagação

- `core/docs/constitution.md`, `core/docs/10-step-protocol.md`, `core/adapters/claude/commands/soma-run.md` e `sonar-audit.md` passam a usar duas tentativas e stop eficiente.
- A cópia live `~/.claude/CLAUDE.md` não foi alterada nesta branch; ela exige ativação manual com o mesmo texto antes de nova run Claude.
- Runs já iniciadas continuam snapshot-lockadas na versão anterior.
